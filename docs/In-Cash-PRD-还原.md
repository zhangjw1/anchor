## 一、概述

### 1.1 目标

In-Cash 是 7709.HK 代币化产品的法币申购与赎回通道：客户以法币（产品计价币种，本期 HKD）申购代币；赎回时先销毁代币，再由上手经 FISL 卖出底层 7709.HK，卖出款回到星路后按净额回款客户普通账户。本文定义 FinOne、FinMix 与上手（Wagmix & Cocoa）、FISL、TaaS、银行之间的订单状态、资金与费用口径、页面与验收要求。

**交付后应达到的可观察结果：**

1. 申购按指示价冻结法币，按实际成交价多退少补；改单成功即确认成交，铸币交付后自动置已完成，无需运营确认结算。
2. 赎回不监控链上打币；不可 Burn 直接拒绝且不产生任何资金、底层与分佣动作；可 Burn 时先销毁后代币对应的底层再卖出。
3. 每一笔法币动作都可通过订单号追溯，银行回执、Issuer 普通户流水与订单金额三处一致。
4. 申购成功后：1）客户持币台账不需要记录；2）结单上应该没有持仓数据（balance 是零）；3）会有资产转出的流水。

### 1.2 范围

**包含：** 申购下单与冻资、系统受理与报单、成交回传与改单（多退少补）、费用拆分与二级托管划转、铸币与自动结算、ETF 成本划付与 FISL 垫资平账、16:30 强制扣款与待结清；赎回下单校验、系统自动受理、可 Burn 校验、链上 Burn 与底层卖出、改单补记费用、出金到账与净额划付；两类订单的状态机、通知、对账与页面展示。

**不包含：** 账户开立、银行 Open Banking / Auto-credit 产品实现、链上 Mint / Burn 技术实现、ETF Order API 与 HKEX 交易实现、自动换汇、RWA 持仓与持仓台账（本产品不登记持仓）。

### 1.3 角色与系统

| 角色 / 系统 | 职责 | 关键约束 |
| --- | --- | --- |
| Market Maker / 客户 | 申购、赎回、打币至 Designated Burn-Wallet、补款 | 申购 quantity 成交后固定；赎回须先自行打币，Gas Fee 自付 |
| FinOne（星企通对客户端） | 下单校验、冻结与扣款、多退少补、资金划转执行、状态同步与回写、客户与 Issuer 普通户台账 | 由 FinMix 驱动状态，FinOne 自动同步；所有资金动作生成双边流水 |
| FinMix | 订单受理、报单上手、改单指令、费用拆分、结算确认、对账；星路金融普通户与星路费用账户 | 驱动订单状态机；费用只按上手回传拆分，不二次计算 |
| 上手 Wagmix & Cocoa | 代币申购 / 赎回指令、ETF Order API 报单、Mint / Burn 指令、成交与结算回传、出金通知 | 成交回传须带 actualPrice、quantity、Total Fee 三字段 |
| FISL 复星证券 | ETF Order API 以 Block Trade 买卖 7709.HK；Margin AC 垫资；Custody / Brokerage AC 转仓；T+2 交割；入金与出金接口 | 入金附带订单号；回传 ETF Order Info 与回执 |

| TaaS / 链上 | Mint 至收币地址、Burn Designated Burn-Wallet 代币；AML/KYC/KYT | 即时扣 Gas Fee；回传 Token 数量与 TxHash |
| 银行 Open Banking / Auto-credit | 法币划付与入账 | 转账附言必须带订单号，以银行回执与对账为准 |

## 二、统一口径与关键定义

### 2.1 金额口径

| 名称 | 定义 / 公式 | 说明 |
| --- | --- | --- |
| 指示价 | Token Indicative Price，Buffer、total price 会按照单独字段进行传递 | 约 1 分钟刷新；仅作下单冻结依据，不构成成交价 |
| quantity | 客户下单的 Token 数量 | 成交后固定不变，多退少补只调整金额 |
| 下单金额 Amount | Amount = 指示价 × quantity | 冻结依据，币种为产品计价币种（本期 HKD） |
| 冻结金额 F | F = Amount | 仅冻结客户普通账户法币；下单费用预估按产品库配置（本期 0） |
| 实际成交价 actualPrice | 上手成交回传的客户成交价 | 以回传为准，FinOne 不自行推算 |
| 费用 Total Fee | 上手回传 total fee，含 finloop fee 与 issuer fee | 由客户承担并计入应付金额 |
| 应付金额 P | P = actualPrice × quantity + Total Fee | 申购改单的重算依据 |
| 多退金额 | F − P（结果大于 0） | 释放冻结差额，再按 P 扣款 |
| 少补金额 | P − F（结果大于 0） | 先追加冻结差额，客户补款后按 P 扣款 |
| 待结清缺口 O | O = P − 实扣金额 | 仅强制扣款路径产生，补足后归零 |
| ETF 成本 | FISL 回传的 ETF 成本（含 Commission） | 由 Issuer 普通户扣划并划付 FISL 平账垫资，不进客户费用 |
| 赎回结算金额 | 上手回传的底层卖出结算金额（在途金额） | 赎回改单与费用计算的金额依据 |
| 赎回净额 N | N = 结算金额 − 实际赎回费（Total Fee） | Total Fee 已含星路分佣与上手佣金，只扣一次；客户实收为净额 |
| 费用三字段 | 实际费用 total fee、星路分佣 finloop fee、上手佣金 issuer fee | 均读自成交回传，不二次计算 |

**取整与比较：** 金额统一比较到法币最小单位，差额不超过 1 个最小单位视为相等。本期不做自动换汇，申购冻结与扣款、赎回回款均使用产品计价币种。下单时费用预估读取产品库配置（本期为 0），实际费用以成交回传改单结果为准。

### 2.2 时间口径

| 时点 / 周期 | 用途 |
| --- | --- |
| 实时 | 指示价约 1 分钟刷新；下单冻结、成交回传、改单、划转逐笔触发 |
| 实时 | 成交改单失败后，告警；邮件通知客户、飞书群内部告警 |
| 16:10 | 当日申购未补足、赎回未到账或未完成划付的预警 |
| 16:30 | 申购补款截止；仍未补足转强制扣款并等待结清（HKT，交易日） |
| 16:45 | 已成交但未收到结算通知的申购订单告警（非待结清订单）；确认无法铸币的退回认购款（刷数） |
| T+2 | 7709.HK 底层交割：申购入库 Issuer Custody AC，赎回卖出交收，均由 FISL 内部完成 |
| 每 1 分钟 | 扫描银行入账回执、Issuer 普通户到账与未完成的划转 / 出金 |
| 每 1 分钟 | 扫描 Market Maker（客户，星企通投资者）账户 balance，拟重启申购的少补流程 |
| 日终（16:30，交易日） | 扫描当日申购、赎回订单，对非终态订单推送飞书内部群告警；订单、法币流水、费用与银行回执、Issuer 台账对账 |

### 2.3 状态语义

- 申购与赎回均不使用「部分成交」「部分到账」；部分到账只体现为待结清缺口 O 减少。
- 申购 quantity 固定；改单只调整实际成交价、实扣金额与费用三字段。
- 申购改单成功即确认成交，不单独设置成交确认节点；赎回改单只补记费用，无多退少补。
- 待结清不是终态：缺口补足转已完成；Issuer 决定不铸币时转人工处理（退款或后续补铸）。
- 赎回的成交与完成分离：改单成功置已成交，卖出款到账、费用拆分并划付客户后才置已完成。
- 铸币、销毁、划转、入金、出金均以订单号作为幂等键，重复通知不重复执行。

### 2.4 与 In-Stablecoin 的口径差异

| 维度 | In-Stablecoin | In-Cash |
| --- | --- | --- |
| 结算币种 | 合规稳定币 | 法币（产品计价币种，本期不做自动换汇） |
| 资金账户 | 客户 VA 户、星路金融 VA 户、Issuer VA 户 | 客户普通户、星路金融普通户、Issuer 普通户 |
| 客户扣款账户 | 客户 VA 账户稳定币 | 客户普通账户法币 |
| 入金与到账 | VA 户内部划转，链上可追溯 | 银行 Open Banking + Auto-credit 入金，附言必须带订单号，以银行回执与对账为准 |
| 底层买卖 | 上手经 FISL 垫资在 HKEX 买卖 | 同；通过 ETF Order API 以 Block Trade 下单，申购回传 Execution Price、Commission 与 ETF 成本，赎回回传数量、Cash Amount 与 FISL 手续费 |
| 费用口径 | 上手回传 total fee / finloop fee / issuer fee | 同；客户侧费用预估按产品库配置（本期 0），成交后改单 |
| 与上手结算 | Issuer 已在星路平台开户，仅变动 Issuer 台账 | 法币需实际划付：申购从 Issuer 普通户扣划 ETF 成本划付 FISL 平账垫资；赎回卖出款先入星路金融普通户，净额再划付客户 |
| 赎回代币 | 自行打币至 Designated Burn-Wallet，不校验链上 | 同；且先执行 Burn 再处置底层资产 |
| Token 交付与持仓 | 链上 Mint 至客户钱包，平台不登记持仓 | 同；Token 直接进入 MM 钱包，平台无 balance 台账 |

## 三、订单状态机

### 3.1 申购

| 状态 | 进入条件 | 可执行操作 | 退出条件 |
| --- | --- | --- | --- |
| 待受理 | 下单校验通过且冻资成功 | 运营受理 / 拒绝 | 已受理或已拒绝 |
| 已受理 | 运营受理且报单上手成功 | 等待底层成交 | 收到成交回传 |
| 待成交 | 收到成交回传，进入改单与多退少补 | 客户补款；再触发改单；资金划转 | 改单成功转已成交；16:30 未补足转待结清 |
| 已成交 | 改单成功，费用与资金处理完成 | 等待铸币 | 铸币交付且自动确认结算 |
| 已完成 | 铸币回传 TxHash，FinMix 自动确认结算 | 只读；后续 ETF 成本划付不改状态 | — |
| 待结清 | 16:30 强制扣款后仍有缺口（O > 0） | 客户补足缺口；Issuer 决定是否铸币或划付 FISL | 缺口结清转已完成；Issuer 不铸币转人工处理 |
| 已拒绝 | 校验失败、冻资失败或人工拒绝 | 只读；释放冻结 | — |
| 处理中 | 划转、入金或回传异常 | 运营重试或补偿 | 恢复原状态或转已拒绝 |

### 3.2 赎回

| 状态 | 进入条件 | 可执行操作 | 退出条件 |
| --- | --- | --- | --- |
| 待受理 | 下单校验通过（无代币冻结） | 系统自动受理 / 拒绝 | 已受理或已拒绝 |
| 已受理 | 系统自动受理且上手确认可 Burn | 等待链上 Burn 与底层卖出 | 收到成交回传 |
| 已成交 | 改单成功，费用三字段补记完成 | 等待卖出款到账；费用拆分与净额划付 | 划付完成转已完成 |
| 已完成 | 卖出款到账、净额入客户账户，运营确认结算 | 只读 | — |
| 已拒绝 | 不可 Burn（余额不足、地址/可销毁校验失败）或校验失败 | 只读；不 Burn、不处置底层、不出金、不分佣 | — |
| 处理中 | Burn、卖出、出金、入金或划转异常 | 运营重试、对账补偿 | 恢复已成交或转人工处理 |

## 四、申购功能需求

### 4.1 下单与冻结

- **下单参数：** 产品、申购类型 In-Cash、quantity、指示价、收币地址~~、Block Trade 标记~~、收付款账户；下单费用预估按产品库配置读取（本期为 0）。
- **校验：** 产品可申购、quantity 满足起投与递增规则及精度、客户法币可用余额不小于 Amount、KYC 与合规有效、收币地址通过 KYT、防重复提交、指示价在有效期内、白名单。
- **冻结：** 仅冻结客户普通账户法币 Amount，可用余额减少、冻结增加并生成流水；校验失败或冻结失败直接返回失败原因（余额不足 / 冻结失败），不生成有效订单。
- **扣款：** 由于架构原因，FinOne 给上手 FinMix 下单时，需要将冻结的客户的钱扣掉给到星路金融大账户 B 端，FinMix 冻结星路金融大账户 B 端。
- **释放：** 订单被拒绝时全额释放冻结或回退扣款；成交进入改单后冻结全额转扣款。

### 4.2 受理与报单

- FinOne 自动受理订单以后向上送 FinMix。
- FinMix 自动受理后置已受理，向上手提交代币申购指令（数量、In-Cash、~~Block Trade~~、~~收币地址~~）；如果上手因为其他原因拒绝订单，则需要 FinMix 同步拒绝订单，并通知 FinOne，执行资金回退到投资者账户。
- 上手经 FISL ETF Order API 以 ~~Block Trade~~ 买入 7709.HK，FISL 以 Margin AC 垫资，报 HKEX 成交后回传 ETF Order Info（数量、Execution Price、Commission、ETF 成本）。

### 4.3 成交回传与改单（多退少补）

- 上手向 FinMix 回传 actualPrice、quantity、total fee / finloop fee / issuer fee、amount（理论上等于 actualPrice × quantity）、total amount（理论上等于 amount + total fee）与成交时间；FinMix 将实际成交资料与 Total Fee 回传 FinOne 并触发改单。
- **重算 P = actualPrice × quantity + Total Fee，与冻结金额 F 比对：**
  - F 大于 P（多退）：释放冻结差额，按 P 扣除客户普通账户法币。
  - F 等于 P：按 P 全额扣款。
  - F 小于 P（少补）：直接追加扣款差额（客户先补款），按 P 扣款。
- **改单成功：** 费用与资金处理成功即改单成功，更新实际成交价、实扣金额与费用三字段，quantity 系统需要支持改单。

### 4.4 费用拆分与法币划转

1. FinMix 按 total fee、finloop fee、issuer fee 拆分费用，不二次计算。
2. 按二级托管层级划转：投资者普通账户法币划入星路金融普通户（在 FinMix），逐级生成双边流水。
3. 将扣的投资者账户款全额划入 Issuer 普通户；FinMix 回传入账确认。
4. 然后再将 finloop fee 从 Issuer 账户扣款至 FinMix 星路费用账户；同时邮件通知 Issuer 到账净额（主题「第三方银行账户入金成功通知」，金额与币种由系统回填）。
5. 任一层级划转失败：不得置已成交，订单保持待成交并转处理中，不得只完成部分层级。

### 4.5 铸币与自动结算

- 已成交后，FinMix 通知上手资金已划转至 Issuer 并指示铸币；上手指示 TaaS Mint 至客户收币地址，执行 AML/KYC/KYT 并即时扣 Gas Fee，回传 Token 数量。
- FinMix 收到结算通知（暗含代币已经铸造完成）后自动确认结算，订单置已完成，无需运营介入；FinOne 自动同步并回写订单。
- 铸币失败时保持已成交。
- 客户可见：实际成交价、实扣金额、费用三字段与已完成状态。
- 如果成交后，在日终截止时间（暂定 16:30）之前上手都无法通知结算（可能铸币平台有问题，无法铸币）；那么此时需要客户款项回退到客户账户。

### 4.6 ETF 成本划付与 FISL 垫资平账（结算后）

- 结算通知（暗含铸币交付）即视为 FinLoop 与 MM 的订单完成；此后星路自动向 FISL 入金（平 ETF 成本的 credit）。
- FinMix 指示 FinOne 从 Issuer 普通户扣划订单金额；FinOne 执行出账并回传扣划完成；注意，给 FISL 打款需要带转账附言。
- FinMix 调用 FISL 入金接口，将 ETF 成本划付 FISL 平账 Margin AC 垫资；FISL 回传入金回执与对账结果，FinOne 回写支出流水。
- T+2 交割 7709.HK 入库 Issuer Custody AC，由 FISL 内部结算，FinLoop 不参与。
- 本节点不改变订单状态。

### 4.7 补款超时与强制扣款

改单因客户余额 / 购买力不足失败时：

- FinMix 保持订单在 **待成交**；资金划转与分佣暂停。FinOne 通知客户补款（邮件）。
- **16:30 前补款：** FinOne 触发再改单；改单成功后 FinMix 置已成交，并走标准资金划转、铸币通知、结算与 ETF 成本划付。
- **16:30 仍未补足：** 强制扣款，扣尽客户账户可用法币（仅部分到账）。
  - a. 通知客户强制扣款结果与剩余缺口。
  - b. 扣款路径：客户账户 → 星路金融大账户 → Issuer 账户。
  - c. 订单保持 **待结清**；FinOne 展示缺口。
  - d. FinOne 通知 Issuer 实际到账金额与缺口；Issuer 决定是否铸币（部分铸币或不铸币）。
  - e. 收到 Issuer 结算通知后，星路向 FISL 入金；**入金金额 = MM 部分到账金额 − total issuer_fee**。
- 无论 Issuer 是否铸币，订单状态仍保持 **待结清**。
- **待结清订单循环结清：**
  - 扫描客户余额；有多少冻多少并划转至 Issuer 账户（按发生顺序处理）。
  - 通知 Issuer；Issuer 铸币完成后回告。
  - 星路向 FISL 打款。
  - 循环直至订单完全结清。单笔订单可能多次结算；处理原则：每一次结算对应一次打款。（经 HSBC 划转的手续费：低于 100w CNY/HKD 无手续费。）
- 说明：MM 资金迟到导致的 Issuer 成本，系统内不考虑。
- 在「待成交」（至 16:30）与「待结清」状态下，星路收到的成交信息（价格、金额等）须在客户端、FinOne、FinMix 展示。

### 4.8 费用与分佣

| 字段 | 来源 / 计算 | 去向 |
| --- | --- | --- |
| 实际费用 total fee | 成交回传 | 由客户承担，计入应付金额 P |
| 星路分佣 finloop fee | 成交回传，不二次计算 | 划转至 FinMix 星路费用账户 |
| 上手佣金 issuer fee | 成交回传，不二次计算 | 计入 Issuer 普通户到账净额 |
| ~~链上 Gas Fee~~ | ~~TaaS 在 Mint / Burn 时即时扣取~~ | ~~按产品约定由客户或 Issuer 承担；不计入费用三字段~~ |

### 4.9 超时未铸币

订单进入 **已成交** 后，满 **30 分钟** 判定：若已成交申购订单仍未收到结算通知（即 MM 尚未收到代币），立即推送飞书内部告警；运营须与上手确认铸币状态。若确认无法铸币，则将全部认购款刷数退回 MM 账户。待结清订单不适用本条，按 4.7 持续循环结清。

#### 4.9.1 判定条件

- **时点：** 每笔订单进入已成交后 30 分钟。
- **订单范围：** 当前状态为已成交的申购订单。
- **「已收到代币」定义：** 以 FinMix 收到上手结算通知（暗含 Mint 完成）为准；不以链上到账时间或 TaaS 单点回调时间为准。
- **排除：**
  - 待结清订单（含强制扣款、部分到账）排除，走 4.7。
  - 已完成或已拒绝订单排除。
  - 尚未进入已成交的订单，由 6.3.1 覆盖。

#### 4.9.2 告警

- **渠道与格式：** 飞书内部群，渐进推送；同批次多笔订单合并为一条列表消息。模板参考：B6。
- **内容：** 订单号、客户、产品、成交时间、实扣金额与币种、当前状态、上手订单号。
- **去重与升级：** 同一订单每日仅告警一次；运营确认后仍未结清的，次日日终按 6.3.1 再告警，直至订单到终态。

#### 4.9.3 处理动作

| 上手确认结果 | 订单处理 | 资金处理 | 客户通知 |
| --- | --- | --- | --- |
| 可铸币，仅延迟 | 保持已成交，不退款 | 不退款；资金保持「已划转至 Issuer」 | 无额外通知；走 A2/A3 |
| 确认无法铸币 | 置终止（原因：铸币失败，退款中） | 将全部实扣认购款刷数退回 MM 账户并生成退款流水；同步冲销 total fee、finloop fee、issuer fee，不再分佣 | 邮件说明退款金额与到账时间（模板 A4） |
| 无响应 / 无法确认 | 保持已成交，飞书群升级跟踪；当日不退款 | 暂不处理；次日日终再告警 | 不通知 |

**刷数口径：** 退款通过刷数恢复客户账户余额，不走自动银行转账。系统侧同步记录订单、费用、分佣与退款流水，以订单号为幂等键（同一订单不可重复退款）。若 Issuer 普通户已收到认购款，运营与上手 / Issuer 确认线下退款路径与到账时间后，在 FinOne 补记线下退款流水，并以订单号关联系统退款。

## 五、赎回功能需求

### 5.1 下单与校验

- **前置：** 客户先将代币转入 Designated Burn-Wallet，Gas Fee 自付；与 Finloop 系统无关。
- **下单参数：** 拟卖出的 Token 数量、MM 出币地址、收付款账户、~~Block Trade 标记~~。
- **校验：** 赎回数量、产品精度、起赎与递增规则、赎回权限、收款账户有效、地址 KYT、防重复提交。
- **明确不校验：** 不监控链上 Transaction、不校验打币地址与金额，默认客户已完成打币；不为赎回冻结代币（RWA 不登记持仓）。
- **校验失败返回原因**，不生成有效赎回单；校验通过返回订单号，状态置待受理。

### 5.2 受理与可 Burn 校验

- FinOne 自动受理，并将订单推送给 FinMix。
- FinMix 系统自动受理（无需运营介入），置已受理并同步 FinOne，向上手提交赎回 / 处置指令（数量、In-Cash、~~Block Trade~~、Designated Burn-Wallet 地址）。
- 上手校验 Designated Burn-Wallet 代币是否可 Burn：余额、地址、链上可销毁性。
- **不可 Burn：** 上手拒绝订单并通知 FinMix，FinMix 将订单置已拒绝终态，不 Burn、不处置底层、不发起出金、不分佣；回传原因，客户核对打币地址与数量后重新下单。
- **可 Burn：** 上手回传上手订单号及受理确认，进入 Burn 与底层处置。

### 5.3 链上 Burn 与底层处置

- **先 Burn：** 上手指示 Issuer Burner Wallet（Fireblocks）销毁 Designated Burn-Wallet 内代币，即时扣 Gas Fee，回传销毁数量与 TxHash。
- **后处置：** Burn 完成后，上手经 ETF Order API ~~以 Block Trade 卖出 7709.HK~~，数量按销毁数量匹配；FISL 先将 ~~7709.HK~~ 由 Issuer Custody AC 调出至 Issuer Brokerage AC（API 转让），再报 HKEX 卖出。
- FISL 回传 ETF Order Info（数量、Cash Amount、FISL 手续费）。
- **顺序约束：** Burn 未完成不得卖出底层；卖出失败保持已受理，由上手重试或运营介入。

### 5.4 成交回传与改单

- **上手回传：** 代币已 Burn（数量）、底层已卖出，并给出 actualPrice、结算金额（在途）、Total Fee / finloop fee / issuer fee。
- FinMix 将成交要素回传 FinOne，FinOne 自动同步成交资料。
- FinMix 下发改单指令（实际费用、星路分佣、上手佣金）；FinOne 补记费用三字段，下单预估为 0，无多退少补、无金额变动。
- 改单成功即确认成交，quantity 不变（但是支持改单），同时录入结算金额与实际赎回费，订单置已成交。
- 赎回改单失败时，订单滞留待成交状态。

### 5.5 FISL 出金、到账与净额划付

1. 上手发出结算通知（代币已 Burn、底层已卖出），提示星路向 FISL 发起出金（含出金金额数据）。
2. FinMix 调用 FISL 出金接口，将底层卖出款划至星路；FISL 回执：卖出款入账星路金融普通户，并带附言。**注意：** 需核对手上 Wagmix 出金通知金额与订单成交信息是否一致。
3. FinOne 收到到账通知后，登记 Issuer 普通户法币流水。
4. FinMix 按成交要素拆分费用：赎回净额 = 结算金额 − 实际赎回费（Total Fee 已分摊，只扣一次）。
5. 划付 finloop fee 至 FinMix 星路费用账户。
6. FinOne 将净额从星路金融普通账户划入客户普通账户，并回传到账确认。
7. FinMix 运营确认结算：订单置已完成；FinOne 自动同步并回写完成状态、费用拆分、法币流水与 TxHash。
8. T+2 卖出交收由 FISL 内部完成，不影响客户回款时点。

### 5.6 异常与挂账

| 场景 | 处理 | 状态 |
| --- | --- | --- |
| 不可 Burn（代币未到位、地址不符） | 拒绝，不 Burn、不处置、不出金、不分佣 | 已拒绝 |
| 出金失败或到账延迟 | 10 分钟扫描重试，16:10 告警，必要时人工对账 | 已成交 |
| 附言缺失或金额不符 | 不自动匹配，挂账待人工认领，不改变订单状态 | 已成交 / 处理中 |
| 费用拆分或净额划付失败 | 重试，未完成不置已完成 | 处理中 |

### 6.3 告警与监控

全部告警经飞书内部群推送，仅面向内部人员。覆盖非终态订单、改单失败、划转 / 出金异常、铸币超时（含 16:45「已收款未到币」告警）及对账异常。

#### 6.3.1 日终非终态订单告警

申购与赎回对账须在 T+0 日终完成。每个交易日日终（暂定 16:30 HKT）扫描仍未到终态的订单并推送飞书群。

| 订单类型 | 终态（不告警） | 非终态（需告警） |
| --- | --- | --- |
| 申购 | 已完成、已拒绝 | 待受理、已受理、待成交、已成交、待结清、处理中 |
| 赎回 | 已完成、已拒绝 | 待受理、已受理、已成交、处理中 |

- **告警内容：** 订单号、申赎方向、当前状态、下单时间、滞留时长、币种与金额（待结清附缺口 O）、卡点环节（受理 / 报单 / 成交回传 / 改单 / 划转 / 铸币 / Burn / 卖出 / 出金 / 入金）、上手订单号、建议处理动作。
- **告警格式：** 一条汇总（非终态总数、分布、涉及金额）加明细列表；多笔可合并一条消息。
- **去重：** 同状态订单每日只告警一次。
- **升级：** 状态变化触发新告警；次日仍非终态则日终再告，直至完成或运营标记。
- **可靠性：** 飞书推送失败按策略重试并记错；告警任务为核心任务，须准时执行。
- **时间窗口：** 日终暂定 16:30，在 16:30 补款截止与强制扣款之后触发；16:10 补款 / 到账预告警保持不变。

#### 6.3.2 铸币超时（16:45）告警

针对已成交但尚未收到代币的申购订单；每个交易日 16:45 HKT 触发一次，作为 6.3.1 的补充。

- **范围：** 当日已成交申购订单；排除待结清、已完成、已拒绝。
- **时点：** 16:45 HKT，在 16:30 强制扣款 / 6.3.1 扫描之后；仅交易日。
- **告警内容：** 订单号、客户、产品、成交时间、实扣金额 / 币种、滞留时长、上手订单号，并提示「请与上手确认铸币状态」。
- **去重：** 不与 6.3.1 重复；16:45 告一次。跨日非终态次日继续。
- **后续：** 确认无法铸币按 4.9 退回 MM 账户；可铸币则记录预计时间并跟踪。
- **模板：** B6。

### 6.4 客户订单通知 FISL

FISL 需按真实业务申购订单授信。需单独建飞书群通知 FISL 业务人员。

- **信息与触发：** MM 下单成功后推送群消息，至少包含：下单时间、方向、数量、预估金额（如有）。

### 6.5 客户结单通知 FISL

FISL 需按真实业务申购订单授信。MM 与 Issuer 的日终结单须通过邮件发送至指定邮箱（地址待定）。

- 金额须带币种符号；时间统一为 HKT（香港时间）。
- 客户邮件模版用语正式，主题、正文与落款不得擅自改动；飞书内部模版用语简洁，仅发给内部业务人员，不发给客户。
- 客户邮件落款统一为「星路金融有限公司」，客服邮箱：CS@finloop.hk，香港服务热线：(852) 3008 8996。
- 「Issuer 到账」邮件沿用现有「第三方银行账户入金成功通知」模版，本附录不重定义。
- 所有通知以订单号为幂等键；重复触发不重复发送。
